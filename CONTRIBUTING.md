# Contributing

Thanks for helping out. This file is the default for every repository in the `mabushi-lab` organization that doesn't have its own `CONTRIBUTING.md`. Where a repo has one, follow that instead.

## Opening an issue

- Search existing issues first.
- Use the issue templates (bug report, feature request or question). For bugs, include steps to reproduce, what you expected, what happened, and your environment.
- One problem or request per issue.

## Opening a pull request

1. For anything non-trivial, open an issue first so we can agree on the approach first.
2. Fork the repo (or branch, if you have write access) and make your change.
3. Keep the PR small and focused. Explain *what* changed and *why*.
4. Add or update tests and docs where relevant. For research code, say which result or figure your change affects.
5. Make sure the project's build and tests pass locally.
6. Fill in the pull request template.

## Branches

Branch from `main` and use a short, descriptive name with a type prefix:

- `feat/<topic>`
- `fix/<topic>`
- `docs/<topic>`
- `chore/<topic>`

## Commits

- Write the subject line in the imperative mood ("Add retry to sync"), 72 characters or fewer.
- Add a body when the *why* isn't obvious.
- Keep commits small and logical. Don't mix unrelated changes.

## Conduct and security

- Participation is governed by our [Code of Conduct](CODE_OF_CONDUCT.md).
- Report vulnerabilities privately. See [SECURITY.md](SECURITY.md). Don't open a public issue.
